# CSS 历史覆盖审计

在仓库根目录运行：

```sh
bun run audit:css
```

生成 `.device-test/css-audit/css-audit.md` 和同目录的 JSON 明细。工具只读分析 CSS，报告包含源文件哈希、规则及声明 ID、旧行号、覆盖来源、条件上下文和仍然生效的选择器分支。

也可以指定文件、输出目录和覆盖线索数量：

```sh
node scripts/audit-css.mjs styles.css --out-dir .device-test/css-audit --max-overlaps 2000
```

整理顺序：

1. 从“完全重复”规则和声明开始。它们要求选择器列表、条件上下文、属性、值和优先级一致。
2. 查看“历史样式区块”和已被覆盖的旧 `!important`，合并同一组件的基础、状态和窄屏样式。
3. 根据“较窄选择器的覆盖线索”追查基础样式与后续补丁。普通声明和重要声明均纳入线索，普通声明不会被当作旧重要声明的覆盖来源；旧规则在其它场景仍可能生效，需要逐项核对。
4. 原生界面验证后，再评估剩余 `!important` 的必要性。保留滚动条的主题样式、悬停显示、顶栏高度和触屏交互。

不同值的声明可能承担兼容性回退，因此标为“需复核”。工具分别分析媒体查询、支持条件、层和嵌套上下文；关键帧不进入删除队列。简写与长写属性、用户主题、外部 CSS、运行期 CSSOM 修改和动态 DOM 需要运行期验证。报告用于定位候选，不推断选择器从未使用。修改 CSS 后重新生成报告。

脚本使用的 PostCSS 解析依赖仅用于开发工具。
